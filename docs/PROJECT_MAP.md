## 1. Общее состояние

Проект **переписан** со старой раскладки (4 отдельных сервиса: backend, MCP-сервер, UI,
PHP-модуль в коробке) на **единый процесс Nuxt 4 + Nitro**. Старый код лежит в `legacy/` — только
как источник для переноса удачных кусков, новыми проверками не покрывается.

Ядро работает и подтверждено вживую. До публикации в Маркете осталось закрыть гейты (§7).

**Автотесты:** около 1500, зелёные в CI на каждый PR. Проверки: `pnpm check` (линт + типы + тесты).

### Попап оценки

После успешного импорта на главной всплывает предложение оценить приложение в Маркете — ✅
проверено. Решение о показе принимается **на сервере**: состояние хранится по порталу, повтор не
чаще раза в несколько дней, после перехода в Маркет попап замолкает до ручной проверки. Факт
оставленного отзыва Маркет по программному интерфейсу не отдаёт, поэтому владелец подтверждает его
сам из карточки «Оценки приложения» на `/queues`.

**Про безопасность разбора.** Модель работает без инструментов и без доступа к порталу: получает
текст, возвращает JSON. Инструкция, спрятанная в документе, не может ничего, кроме как испортить
свой же JSON. Раньше агент имел инструменты — при большом ревью это нашли как **критичную** дыру
(можно было вытащить секреты) и убрали.

## 6. Инфраструктура

| Часть | Состояние | Комментарий |
|---|---|---|
| Очереди BullMQ + Redis | ✅ проверено | Четыре очереди: события, извлечение, распознавание, запись |
| Масштабирование воркеров | 🧪 сделано | Обработка — на N реплик; события и кроны — на одном |

Раз в 5 минут проверяются три вещи: не разгребается (самая старая задача висит >20 мин), задачи падают (10+ за 15 мин), очередь не читается. Как это работает и почему именно так — [`PROCESS.md`](PROCESS.md) §11.2; две отвергнутые версии правила разобраны в шапке `server/utils/queueAlert.ts`, чтобы не изобрести заново. ⚠ вживую не проверялось, канал не подключён |
| Нагрузка на очередь | ✅ проверено | `pnpm loadtest:queue --jobs 2000 --portals 20`: ничего не потеряно, очередь ушла в ноль. ⚠ обработчик в прогоне — заглушка с паузой: измерена очередь, а не полный путь документа |

Проверки подтверждены мутациями — при отключении повторов и при подмене паузы на фиксированную сценарий краснеет |

**Расчётная пропускная способность: ≈ 900 документов в час на портал.** Это **оценка, а не замер**:
ограничитель Битрикс24 даёт ~2 запроса в секунду, один документ стоит примерно 8 обращений (число
обращений взято из кода, вживую не считалось). Упирается в портал, а не в очередь: очередь backlog
держит и разгребает полностью — вот это как раз измерено.

## 7. Что мешает выпуску в Маркет

| Гейт | Состояние |
|---|---|
| Реальный клиент провёл реальный импорт на своём портале | ⛔ **блокер** — был только засеянный тест-портал |
| Юридическое решение по облачной нейросети | ✅ решено — по умолчанию BitrixGPT, уход от прямого КНР-инференса |
| Опубликована политика конфиденциальности по HTTPS-адресу | ⛔ **блокер** — черновик готов, нужны поля владельца и вычитка юристом |
| Прод стабилен, установка и удаление отрабатывают | 🔨 в работе |
| Карточка Маркета: тексты, скриншоты, права | 🔨 в работе |
| Тариф | ⏸️ отложено — решение владельца |

**Отдельно: что написано и покрыто тестами, но ни разу не работало вживую.** Это не блокеры выпуска
сами по себе, но выпускать, не увидев их в деле, рискованно:

- **сообщения сотруднику и в чат ошибок** при неудачном импорте — ни одно не отправлялось;
- **отказ по частоте загрузок** (40 за 10 минут) — не срабатывал;
- **тревоги о неполадках очередей** — не срабатывали, телеграм-канал не подключён;
- **запись в смарт-счёт и смарт-процесс** как цель — полного прохода не было;
- **изоляция метрик между порталами** — подтверждена только тестами, второго портала не было.

Плюс ограничение частоты загрузок считается **в памяти процесса**: если HTTP-роль когда-нибудь
размножат на несколько экземпляров, защита молча перестанет работать (см. §9).

⚠ Владельцу отдельно: сверить с Битриксом условия маршрутизации BitrixGPT (AI Router может
проксировать к сторонним моделям) и честно указать в карточке и политике, что **текст документа
уходит на внешний инференс**.

## 12. Чек-лист приёмки

То, что **нельзя** закрыть автотестами — прогоняется руками на портале. Два списка: §12.1 —
разблокировочный заход по непроверенному прямо сейчас, §12.2 — полный чек-лист перед выпуском.

### 12.1. Живой заход: то, что ни разу не работало на настоящем портале

Это **не** полный чек-лист выпуска (он ниже, §12.2). Это список того, что написано, покрыто тестами
и помечено 🧪 — но **ни разу не наблюдалось в работе**. Сегодня это главный риск проекта: код есть,
уверенности нет.

Взято не всё помеченное 🧪, а то, что **видно снаружи**: что появляется в CRM, что приходит человеку,
где приложение отказывает и не течёт ли между порталами. Инфраструктурное (сверка `member_id`,
надгробия событий, продление токенов, масштабирование воркеров, телеметрия, вариант «Вайбкод»)
глазами за один заход не проверить — это подтверждается работой прода, и такие строки останутся 🧪
дольше.

Порядок — по местам, а не по важности: сначала всё, что делается за один заход в один портал, потом
то, для чего нужен прод, потом то, для чего нужен второй портал. Так не приходится открывать одну и
ту же карточку дважды.

- [ ] Поднять Redis обратно — пришло **«восстановилось»**.
- [ ] **«Не разгребается»**: остановить контейнер-обработчик, загрузить документ, подождать 20+ минут.
      Ожидается одно сообщение, а **не** по одному на каждую пятиминутную проверку.
- [ ] Оставить поломку висеть час — второго сообщения об одном и том же **не приходит**.
- [ ] `/queues` открыт: возраст последней проверки виден, «ещё не проверяли» отличается от «всё
      хорошо».
- [ ] **Упавшие задачи**: в карточке видны причина и время; «Повторить» возвращает задачу в работу,
      «Отбросить» убирает насовсем.
- [ ] **Переавторизация портала** из карточки «Порталы» проходит без ошибок.
- [ ] **Вернуть всё в строй**: Redis поднят, обработчик запущен, `/queues` показывает пустые очереди
      и отсутствие тревог. Дальше без этого нельзя.

- [ ] 👍 на строке результата портала A → в счётчиках B отзыв **не появился**.
- [ ] Настройки A не видны и не меняются с B.

#### Итог захода

- [ ] Все строки 🧪, которые заход подтвердил, переведены в ✅ в этой карте — **в том же PR**.
- [ ] Всё, что воспроизвести не удалось, отмечено честно: «не проверено», а не «работает».
- [ ] Найденные дефекты заведены задачами со ссылкой на пункт чек-листа.

Блоки 0–5 и 8 делаются на одном портале примерно за полтора часа (плюс время на пять пачек в
блоке 5 — каждый принятый файл реально уходит в нейросеть). Блок 6 требует прода и возможности
останавливать контейнеры, блок 7 — второго портала.

**Чего этот заход НЕ закрывает** — чтобы не возникло ложного ощущения полноты:

| Что остаётся 🧪 | Почему не глазами |
|---|---|
| Сверка `member_id` при установке, надгробия событий | Проявляются только на подделанной или переигранной установке |
| Продление токенов по крону | Ждать 180 дней или подкручивать даты в базе |
| Масштабирование воркеров | Нужно несколько реплик и нагрузка |
| Телеметрия, вариант «Вайбкод» | Отдельные развёртывания |
| Понятный отказ входа оператора, разделы консоли | Служебное, не влияет на клиента |
| Опрос статусов POST, история загрузок, три состояния экрана | Покрыто тестами интерфейса; заход их заденет мимоходом, отдельных пунктов нет |
| Проверка ответа модели, правила по словам, предупреждение о поставщике | Всплывут по ходу блоков 2–5; отдельно не выделены |

Эти строки снимет работа прода, а не один заход. Помечать их ✅ по итогам этого чек-листа нельзя.

### 12.2. Полный чек-лист выпуска

**Установка и права**
- [ ] Установка на чистый портал: события привязались, токен сохранён, `/install` показал диагностику.
- [ ] Удаление приложения: данные портала стёрты, повторная установка проходит заново.
- [ ] Не-администратор не может сохранить настройки (проверять **ответ сервера**, а не только вид формы).
- [ ] На ненастроенном портале рабочая часть скрыта; администратор видит кнопку, сотрудник — текст.

**Разбор документа**
- [ ] PDF с текстовым слоем, PDF-скан, фото с телефона, Excel, Word — все доходят до CRM.
- [ ] Документ на белорусском и на казахском: метка налогового номера найдена.
- [ ] Файл не того формата, пустой, больше 20 МБ — понятный отказ, задание не создаётся.
- [ ] Съёмка камерой в мобильном приложении Битрикс24 открывает «Файлы / Фото / Камера».

**Деньги** (самое дорогое при ошибке)
- [ ] Цены с НДС и без НДС; разные ставки в строках; ставка 0 → «Без НДС».
- [ ] Печатный итог расходится с расчётом — предупреждение, сумма из сверенного расчёта.
- [ ] Строка со скидкой уменьшает сумму записи.
- [ ] Ставки НДС нет в портале / валюты нет в портале → импорт остановлен, сообщение в чат ошибок,
      в CRM **ничего не создано**.

**Подбор**
- [ ] Поставщик найден по налоговому номеру; не найден → запись без компании + предупреждение.
- [ ] Товар найден по торговому предложению, по свойству артикула, по внешнему коду, по имени.
- [ ] Товар не найден: обе настройки — пропуск строки и произвольная позиция.
- [ ] Незнакомая единица измерения → подстановка по умолчанию + предупреждение.

**Цели**
- [ ] Сделка, лид, смарт-счёт, смарт-процесс — каждая как цель.
- [ ] Правило по словам перебивает цель по умолчанию; ручной выбор для файла перебивает правило.
- [ ] Удалённое направление → запасная цель + предупреждение.
- [ ] Портал без лидов: вариант «Лид» скрыт, сохранённый лид уходит в сделку.

**Повторы и целостность**
- [ ] Повторная отправка того же файла не создаёт вторую запись (`pnpm verify:idem`).
- [ ] Пачка файлов: уходят по одному, статус по каждому виден.

**Результат в портале**
- [ ] Копия файла на Диске открывается по ссылке из списка операций.
- [ ] Запись в таймлайне видна **и** в компании, **и** в созданной сущности.
- [ ] Сообщения приходят в оба чата; разметка из документа обезврежена (`[url=...]` не сработал).

**Интерфейс**

- [ ] Мобильное приложение Битрикс24: нет дубля заголовка, скрыты шестерёнка и ссылка на метрики.
