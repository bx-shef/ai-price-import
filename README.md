# procure-ai — AI-импорт прайсов в Битрикс24

> Last reviewed: 2026-07-30

Облачное приложение Битрикс24 Маркета (мультитенант, OAuth). Сотрудник загружает документ с
таблицей — накладную, счёт, коммерческое предложение или прайс, — приложение распознаёт его
нейросетью, находит поставщика и вносит позиции в нужную сущность CRM.

Издатель — ИП Шевчик И.С.

## Стек

Nuxt 4 + Nitro **одним процессом**, BullMQ + Redis (очереди), Postgres (токены порталов и счётчики),
интерфейс на Bitrix24 UI. Распознавание — OpenAI-совместимый вызов: BitrixGPT по умолчанию, DeepSeek
или свой эндпоинт как опция.

Все обращения к Битрикс24 идут через официальный SDK со встроенным ограничителем запросов.
Модель работает **без инструментов**: получает текст, возвращает JSON — и всё.

## Раскладка

```
app/          интерфейс: страницы, компоненты, чистые функции (+ тесты)
server/       backend: api, очереди, работа с Битрикс24, разбор нейросетью
tests/        автотесты (чистое ядро + компоненты)
scripts/      живые проверки и нагрузочные прогоны (не входят в сборку)

deploy/       выкладка
legacy/       старый проект до переписывания — только для переноса кусков, не собирается
```

Подробнее, с состоянием каждой части, — [`docs/PROJECT_MAP.md`](docs/PROJECT_MAP.md) §10.

## Быстрый старт

```bash
cp .env.example .env          # заполнять для локальной работы почти ничего не нужно
docker compose up -d db redis # Postgres и Redis из compose-файла репозитория
pnpm install
pnpm dev
```

Приложение поднимется на `http://localhost:3000`. Без Redis очереди не работают: страница откроется,
но загрузка документа получит отказ «сервис обработки временно недоступен» — это ожидаемо, а не
поломка. Все переменные с пояснениями — в `.env.example`.

**Живые проверки против настоящего портала** (`pnpm verify:*`, `pnpm live:crm`) требуют вебхука
тестового портала в `.env.b24test` и ключа нейросети. Оба файла в репозиторий не коммитятся —
координаты берутся у владельца.

## Команды

```bash
pnpm check        # линт + типы + все тесты (это гоняет CI)
pnpm dev          # дев-сервер
pnpm test         # тесты
pnpm build        # сборка одного Nitro-процесса
```

**Живые проверки** — требуют доступа к тестовому порталу и ключа нейросети (в репозиторий не
коммитятся):

```bash
pnpm sdk:smoke      # транспорт к порталу: 30 запросов подряд без отказа
pnpm verify:chat    # распознавание документа нейросетью
pnpm live:crm --ai  # полный проход: текст → нейросеть → сделка с позициями → уборка
pnpm verify:idem    # повтор одним идентификатором не создаёт дубль
pnpm loadtest:queue # очередь под нагрузкой + реальный темп ограничителя Битрикс24
```

## Разработка

- **В `main` не пушим** — только через PR. Мержит владелец.
- Комментарии в коде — по-английски; всё, что видит пользователь, и документация — по-русски.
- Чистые функции отделены от ввода-вывода и покрыты тестами; данные из портала выводятся только
  через экранирование.
- Каждый документ в `docs/` и в корне несёт строку `> Last reviewed: ГГГГ-ММ-ДД`.

## Производительность

**≈ 900 документов в час на один портал.** Упирается в ограничитель Битрикс24 (около 2 запросов в
секунду), а не в очередь: очередь backlog держит и разгребает полностью, приём нового документа
остаётся мгновенным. Подробности — [`docs/PROCESS.md`](docs/PROCESS.md) §13.
